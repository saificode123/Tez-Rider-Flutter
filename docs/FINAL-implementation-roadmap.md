## Stage3 — Biometric login

Existing packages: local_auth^2.3.0 and flutter_secure_storage^9.0.0. Declared constraints are observed, not an upgrade recommendation. Android has USE_BIOMETRIC and FlutterFragmentActivity. iOS has NSFaceIDUsageDescription and target15.0; runtime/signing unavailable on this Windows host.

AuthController detects support, stores bio_enabled and calls local authentication with biometricOnly:false/stickyAuth:true. Login stores tr_refresh/tr_role; biometric login reads refresh token, calls setSession, account gate and database profile, then routes customer/vendor/rider/admin or pending/CNIC. Logout resets gate/presence, attempts signOut, deletes tr_refresh/tr_role and user_logged_in; signOut failure swallowed. No biometric-specific lifecycle acceptance tests identified. Secure storage usage is not proof every SDK session copy is hardware-gated. Enrollment completion/account binding, SDK auto-restoration, preference-reset/logout behavior and token rotation synchronization need dedicated inspection.

## ApprovalA — Payment strategy

COD is not a substitute for HMAC-callback verification in the traceability matrix. Never mark COD captured at checkout or assume delivery OTP proves cash collected. A sandbox does not transfer real money.
